# 端侧人流检测与 GB28181 告警上送验收清单

用途：按 `task.md` 的依赖顺序记录实施、测试和发布门禁。未完成或无证据的项目不得标记为完成。

## 提交前范围检查

- [x] `spec.md`、`plan.md`、`task.md` 和本清单的术语、默认值、边界一致。
- [x] 初始提交不包含生产代码改动、不包含未经真板验证的 RockIVA 固化参数。
- [x] 所有 T0-T12 任务均有独立票据，且 `Blocked by` 与依赖图一致。
- [x] 当前目录的构建产物、SDK 源码、模型、二进制和代码库索引未被误加入规划提交。

## T0 基线与回滚

- [x] 采集、编码、点播、注册、INVITE、ACK、BYE 的当前行为已记录。
- [x] 分析关闭时主视频路径回归通过（当前实现没有分析分支，宿主回归通过）。
- [x] 固件、配置、工具链、测试命令和基线时间已记录；未获得的板端/WVP 运行态信息已明确标记未验证。

## T1 真板 RockIVA 探针

- [ ] 真实 RV1126B 型号、固件和 RockIVA 库版本已记录。
- [ ] 候选模型、输入尺寸、帧率、核心掩码和结果模式均有实测数据。
- [ ] person 检出、`objId/state` 变化和流纪元边界有录制结果。
- [ ] DMA-BUF/物理地址输入、release callback、停止和重启无泄漏/UAF。
- [ ] 分析启停不影响主编码和点播。

## T2 观察结果与配置契约

- [ ] 契约版本、时间单位、坐标系、缺失值和时钟状态已固定。
- [ ] 配置非法值启动即拒绝，默认关闭分析。
- [ ] 重复帧、乱序帧、流重置和配置版本变化均有确定性测试。
- [ ] 测试夹具不依赖 NPU、墙钟或 SIP `SN`。

## T3 常驻分析分支

- [ ] 采集启动即建立分析分支，不依赖 INVITE/点播。
- [ ] 分析队列有界且采用最新帧策略，丢帧计数可观测。
- [ ] 推理异常、超时、队列满时主视频仍持续输出。
- [ ] 输出观察结果携带通道、流纪元、帧 ID、PTS 和后端版本。

## T4 事件引擎

- [ ] 确认、去抖、消失宽限、冷却和重配置测试通过。
- [ ] ROI 当前人数与方向性增量分别断言。
- [ ] `START/UPDATE/END`、`event_id`、事件序号和结束原因稳定。
- [ ] 不宣称跨摄像机或全局唯一人数。

## T5 证据与持久桥

- [ ] 精确帧优先，近邻帧降级包含帧差和近似标记。
- [ ] JPEG 原子发布、校验和、保留、过期和容量上限测试通过。
- [ ] 事件先持久化再通知，游标、ACK、resume 和断线重放通过。
- [ ] 队满优先保护 START/END，并统计 UPDATE 合并/丢弃。

## T6 daemon Outbox 与标准 Alarm

- [ ] daemon 重启后未确认事件可恢复，幂等键稳定。
- [ ] Alarm/Evidence sink 状态独立，成功 sink 不重复发送。
- [ ] 黄金 XML 和解析器断言覆盖转义、时区、Unicode、序号回绕和必需字段。
- [ ] 标准 Alarm 不包含 JPEG/Base64/本地路径，默认只发送 START。
- [ ] SIP 超时、拒绝、未注册和重试耗尽可观测。

## T7 精确证据 Sink

- [ ] 图片内容在确认前有持久副本或租约。
- [ ] HTTP 认证、校验和、幂等、退避、重试和死信测试通过。
- [ ] 图片与 Alarm 可乱序到达，证据失败不阻塞 Alarm。

## T8 stock WVP 兼容

- [ ] stock WVP 接受并展示标准 Alarm。
- [ ] WVP 近邻抓图与端侧触发帧差异已记录并对外说明。
- [ ] 重复 Alarm、SIP 重试和平台拒绝行为已验证。

## T9 可观测性、隔离与打包

- [ ] 推理、跟踪、事件、证据、日志、订阅、SIP、时钟和降级指标齐全。
- [ ] NPU、存储、socket、SIP、HTTP 故障注入不停止主视频。
- [ ] 模型、库、配置、自启、容量上限和回滚路径可检查。

## T10 exact-evidence WVP 适配器

- [ ] `event_id/evidence_id` 关联幂等，支持任意到达顺序。
- [ ] 重复请求、重启恢复、校验失败和过期证据状态清晰。
- [ ] 适配器不修改标准 Alarm 的必需字段语义。

## T11 stock WVP 真板发布

- [ ] 标注场景精度、召回率、ID switch 和方向计数误差达到发布阈值。
- [ ] 触发到 Alarm 时延、CPU/NPU/RGA、内存、温度和丢帧达到预算。
- [ ] 编码连续性、背压、断线重放、重启恢复和 24 小时稳定性通过。
- [ ] 发布记录包含板卡、固件、模型、配置、阈值和已知限制。

## T12 exact-evidence 发布

- [ ] 触发帧、JPEG、PTS、采集时间和校验值可端到端关联。
- [ ] 断线、乱序、重复、保留上限和重试耗尽行为通过。
- [ ] exact 失败可按策略降级为 Alarm-only 或 stock 拉图，并可观测。
- [ ] 发布、回滚和运维说明已完成。
