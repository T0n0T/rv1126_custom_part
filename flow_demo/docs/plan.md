# flow_demo 实施计划

## 状态

当前已完成项目初始化和第一批视频素材接收，并已准备跨机器训练代码。视频尚未标注，模型尚未训练；先完成素材审查、抽帧和标注准备，再进入视觉模型与 SSV 裁剪实现。未获进一步实施确认前，不复制 SSV 源码或修改 SDK 生产代码.

## 阶段 1：需求基线与数据准备约定

- 固化 `docs/spec.md`、本计划和 `dataset/README.md`。
- 已收到 `dataset/raw_videos/` 下 11 段视频；PC 端逐段完整解码通过。个别文件带有手机容器元数据和非单调 DTS 警告，但当前未发现解码失败。
- 下一步从视频生成低频预览帧和动作关键帧，人工确认柜内、过渡区、柜外是否全程可见，并记录每段视频的开关门区间与动作真值。
- 后续统一 sidecar、事件记录和区域配置格式；在格式确定前不把示例值当作真实柜体配置。
- 确认机位覆盖柜内、柜口过渡区和柜外，确保目标穿越时可见。

## 阶段 2：验证跟踪与穿越判定核心

- 从 `wvp-ssv` 选定并记录清洁、固定的源 commit，审阅 BoT-SORT 源码依赖和许可证。
- 仅复制所需 tracker、Kalman、matching、assignment 和必要 GMC 支撑文件及相关测试；GMC 首版关闭。
- 使裁剪后的核心不依赖 GStreamer，可接收统一检测帧序列；核实板端编译器的 C++20／`std::span` 支持，必要时先调整兼容层。
- 新写纯 C++ 区域状态机、会话、往返事件和合并逻辑。
- 用人工构造检测框序列覆盖单支、多支、往返、折返、丢失、观测间隔过大和会话结束；PC 自动测试通过后再做板端交叉编译／运行检查。
- 该阶段只验证给定检测输入时的跟踪和判定，不宣称视觉检测有效。

## 阶段 3：SDK 与 RKNN 技术验证

- 核实当前 RV1126B SDK 的 RKNN API、头文件、运行时库、驱动和可用转换工具版本及 ABI 对应关系。
- 使用简单已知模型验证电脑端 ONNX 到 RKNN 转换、INT8 校准、量化张量属性与板端加载／推理调用。
- 核实候选 YOLOv8n 导出图的算子支持、输入输出布局、量化参数以及后处理契约。
- 分开记录编译通过、模型转换通过和板端推理通过，不能互相替代。
- 先实现普通内存输入的正确性路径；是否使用 RGA、DMA-BUF 或其他硬件预处理由性能数据决定。

## 阶段 4：机位试拍与数据集

- 首轮建议采集 200–300 张不同款式、颜色、朝向、柜内摆放、遮挡和光照的安全帽照片，以及 10–12 段短视频。
- 先审核机位可见性；不合格时先调整柜体、镜头或补光，不进入大规模标注。
- 视频分别覆盖单顶取放、多顶连续动作、空手／区域内移动、折返／停留和手部遮挡／多顶重叠合并等场景；过渡区必须始终在画面内。验证目标是安全帽本体穿越柜口，不是佩戴安全帽的人进出画面。
- 用完整视频／会话先划分训练、验证、测试，再从训练视频抽帧，防止相邻帧泄漏。
- 照片与视频抽帧的检测框由工具辅助标注，人工复核；动作方向、数量、时间及开关门真值必须由人确认。
- 试拍数据不自动等同最终独立测试集；需明确锁定 holdout 测试素材。

当前训练工具已就绪：`training/prepare_dataset.py` 从 `dataset/PPE.zip` 读取 YOLO 标注，只保留 `helmet` 并生成可移动的单类别数据集；`training/train.py` 负责 YOLOv8n 微调；`training/export_onnx.py` 负责静态 FP32 ONNX 导出。当前只完成代码和 ZIP 格式检查，尚未生成数据集副本、训练权重或 ONNX 结果。

## 阶段 5：模型训练与推理抽象适配

- 从通用预训练权重微调单类别 `helmet` YOLOv8n，起始输入尺寸 640×640。若评估可用的安全帽预训练模型，将其作为候选基线测试；不假设其训练场景与柜内散放安全帽相同，也不未经对比就取代本项目数据训练。
- 在 PC 上评估检测质量；导出 ONNX 并用独立验证素材检查类别和框坐标。
- 将必要的 SSV `ssv-infer` 核心及插件源码复制到本项目，记录源 commit、文件清单、许可证和改动；不链接 SSV 工作树。
- 在项目副本中将 float-only tensor view 调整为带数据类型、字节跨度和量化参数的 tensor view；改造 YOLO parser 在需要时读取反量化值。
- 新增 RKNN backend 和配置／构建接入；保留 PC ONNX backend 用于交叉验证。
- 将训练模型转换为 RKNN INT8，比较 ONNX 与 RKNN 检测结果，再验证板端运行和输入图像坐标映射。

## 阶段 6：GStreamer 集成与事件输出

- 将必要 SSV `ssv-track` 插件与 BoT-SORT 源码复制并独立维护，关闭 GMC；保留 tracker 和插件适配测试。
- 集成媒体解码、infer、track、独立 crossing 元素和 event sink；优先完成文件输入管线。
- crossing 接收跟踪元数据、PTS、会话状态及归一化区域配置；event sink 负责日志和 JSONL，不参与判定。
- 明确 buffer/meta 所有权及复制、坐标变换和 PTS 语义；避免依赖过度复杂的 SSV 全局 source-meta 生命周期。
- 文件回放采取阻塞回压；实时模式使用有界队列及可观测的旧帧丢弃策略。

## 阶段 7：分级验收

1. PC 人工检测序列测试 tracker 与 crossing。
2. PC 端视频和 ONNX 回放，输出动作事件与会话完整性。
3. RV1126B 文件解码、RKNN 推理、BoT-SORT 和事件输出端到端回放。
4. 固定摄像头实时运行，检查丢帧、PTS 间隔、事件延迟和不确定处理。
5. 使用独立锁定测试集计算动作级精确率、召回率、负样本误报及不确定案例结果。

动作级验收目标暂定为精确率 ≥95%、召回率 ≥90%，负样本不产生确定事件。须在样本量和评测脚本充分后报告指标，不足时说明限制。

## 技术风险与验证门

- 当前 SDK 中能找到 RKNN 相关运行时／头文件，不代表匹配的模型转换工具、NPU 驱动、ABI 或 YOLO 算子已验证。
- SSV 推理接口、内存所有权、插件调度复杂度高；必要时只裁剪可独立的部分，不为追求源码复用而纳入 Runner、Agent、Redis 或知识库。
- SSV 跟踪类型使用 C++20；交叉编译器是否支持目标标准需实测。
- INT8 量化、预处理、NMS 和小目标检测可能影响精度；必须以真实柜体素材及板端结果调整。
- 视觉遮挡和轨迹 ID 切换影响逐支计数；不可确认时应拒判，而非由库存差补造动作。
- 实时最大观测间隔、模型置信度、事件合并窗口之外的阈值均需数据驱动设定；首轮只将合并窗口以 1 秒作为可调起点。

## 阶段交付边界

- 首个代码里程碑：人工检测序列驱动的 tracker／crossing 测试与可记录结果；不包含真实视觉检测验收。
- 首个视觉里程碑：PC 上真实素材的 ONNX 检测和动作回放。
- 最终 Demo 验收：RV1126B 板端文件回放成功，并进一步完成实时摄像头验证。
