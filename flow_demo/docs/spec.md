# flow_demo 需求规格

## 状态

本文记录截至 2026-11-06 已口头确认的首版需求。项目仍处于初始化阶段，尚未实现或验证视觉链路。

## 目标

构建独立的 RV1126B 售卖柜物体出入检测 Demo，以单类别安全帽 `helmet` 为例。系统以柜口过程视频识别逐次取出与放入动作，按临时轨迹计数，保留不确定情况的说明，并可在 RV1126B 上独立运行。

电脑端负责采集管理、标注、模型训练、模型转换、PC 回放与评测；板端负责视频解码、检测、跟踪、穿越判定和事件记录。最终验收必须包含板端实跑。

## 输入与运行模式

- 首阶段输入为预录视频；通过 sidecar 为每段视频指定会话 `open_pts_ms` 和 `close_pts_ms`。
- 会话时间使用视频源 PTS 表示，不使用处理完成的墙钟时间。
- 前后静态图片可用于辅助数量核对；图片本身不作为逐次取放动作的证据。
- 后续可使用固定机位实时摄像头。首版允许专门布置柜体、机位和补光，并要求物体穿越柜口时有足够连续可见画面。
- 文件回放采用阻塞回压并尽量处理每帧；实时模式使用有界队列，可丢弃旧帧。所有观测保留原始 PTS 和帧序号。

## 模型与流水线

- 检测类别只有 `helmet`，检测安全帽本体；不做人头／佩戴状态识别，不区分颜色、款式或单顶安全帽的永久身份。
- 训练基线为从通用预训练权重微调 YOLOv8n，单类别，输入 640×640。该基线尚未通过训练、精度或性能验证。
- 电脑端负责训练、ONNX 导出和 RKNN INT8 量化；板端部署 RKNN 模型及匹配的运行时依赖。
- 目标媒体链路为 GStreamer 解码与调度、SSV `ssv-infer` 推理结构（新增 RKNN 后端并允许修改上层抽象）、SSV `ssv-track`／BoT-SORT 跟踪、本项目穿越与事件元素。
- 推理抽象须能表达 `float32`、`int8`、`uint8` 等张量及量化参数。RKNN 输出不应被迫在 backend 内无条件复制为 float；parser 在需要时按张量类型和量化参数读取。
- SSV 必要源码复制到本项目独立维护。复制时记录源 commit、裁剪文件、许可证及本地差异；不依赖 SSV 工作树路径。
- 不预先承诺 RKNN Toolkit、模型导出算子、NPU 输入格式、硬件预处理或零拷贝路线；这些需以当前 RV1126B SDK 和板端实测为准。

## 逐次动作语义

画面按原始视频坐标配置 `inside`、`transition`、`outside` 三个区域。区域使用归一化坐标，启动时校验边界和顺序；检测预处理的缩放、letterbox 或旋转必须映射回原始坐标后再判定。

- 轨迹满足 `inside → transition → outside`，确认取出 `take_out`。
- 轨迹满足 `outside → transition → inside`，确认放入 `put_in`。
- 每次完整有效穿越产生一次逐支动作；同一 `track_id` 后续反向完整穿越可再次产生事件。
- 过渡区内折返、轨迹丢失、目标合并或无法满足可见性约束时，不猜数量，记录 `uncertain` 原因。
- 同方向且时间相邻的逐支穿越按初始 1 秒可配置窗口合并成一次事件，保留涉及的 `track_ids`；该窗口需通过数据评测调整。
- 观测间隔按源 PTS 计算。超过待配置上限时，不可跨越缺失区间确认动作，应重新建立区域状态或标记不确定。
- 会话关闭时仍未完成的穿越记为不确定；会话存在任何未解决的不确定过程时，`result_complete=false`。已确认动作仍保留，但不把部分净变化表达成确定总数。

## 输出契约

首版只输出简洁日志及 `events.jsonl`，不实现完整 UI 或 WVP 接入。事件记录至少包含：

```json
{
  "event_id": "session-001-event-003",
  "session_id": "session-001",
  "direction": "take_out",
  "count": 2,
  "track_ids": [12, 15],
  "status": "confirmed",
  "start_pts_ms": 4200,
  "end_pts_ms": 5900,
  "start_frame": 126,
  "end_frame": 177,
  "reason": "",
  "evidence": {
    "video": "take_out_001.mp4",
    "start_pts_ms": 4200,
    "end_pts_ms": 5900
  }
}
```

`direction` 为 `take_out`／`put_in`；`status` 为 `confirmed`／`uncertain`／`rejected`。首版只引用原视频与 PTS／帧号，不在实时流水线裁剪片段。会话摘要单独报告确认取出、确认放入、不确定过程和 `result_complete`。

## 数据与标注

- 检测训练集以安全帽摆拍照片为主，辅以真实柜体视频抽帧；检测标注为单类别 YOLO 框。当前收到的 `dataset/PPE.zip` 是 Roboflow YOLOv8 六类 PPE 数据集，训练准备阶段只保留 `helmet` 并重映射为 class `0`，不能把其余 PPE 类别直接混入当前出入检测器。照片覆盖不同款式、颜色、尺寸、朝向、柜内摆放、柜口穿越、反光和遮挡。
- 动作评测集保留完整视频及人工真值，记录动作方向、数量、时间范围、开关门 PTS 和不确定原因。
- 训练、验证和测试按完整视频或完整会话划分；同一视频的相邻帧不得跨集合。
- 空手伸入、柜内移动、过渡区折返、遮挡、多个安全帽重叠／合并应出现在评测素材中。首版要求过渡区持续处于摄像头可见范围内，不把“关门后过渡区不可见”作为常规场景。负样本应覆盖帽子、球体、碗状物、头部／衣物、包装物等易混淆物；这些只用于降低误报，不作为 `helmet` 正样本。
- 首轮建议先拍约 200–300 张照片和 10–12 段短视频做机位与可见性试拍；数量是采集建议，不是已确认的最低数据规模，也不代表这些试拍视频应全部作为最终测试集。

## 验收目标

以下为暂定目标，不是现有结果：

- 动作级事件精确率不低于 95%。
- 满足可见性约束的真实动作，动作级事件召回率不低于 90%；`uncertain` 不计作成功检测。
- 空手伸入、区域内移动和折返负样本不产生确定出入事件。
- 约束外严重遮挡等案例应避免猜测，并按规则报告不确定。
- 最终验收顺序为 PC 视频回放、RV1126B 文件回放、实时摄像头；明确分别报告各阶段结果。

## 非目标

- 不做多摄像头融合、安全帽颜色／款式分类、单顶安全帽身份识别、佩戴状态识别或不可见遮挡下的数量推断。
- 不做售卖柜业务、支付、库存服务、用户界面或 WVP 集成。
- 不修改上级目录现有 `media_engine`／GB28181 生产主流程。
- 不把 PC 结果、模拟序列或源码检查当作板端端到端验收。
