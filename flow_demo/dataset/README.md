# 数据集准备

本目录用于保存采集、标注和划分说明。当前已收到 `raw_videos/` 下 11 段手机录制视频，尚无照片、标签或训练模型。原始视频已完成 PC 端完整解码检查，但尚未完成机位真值审核和目标标注。

## 当前视频清单

当前视频用于机位审查、抽帧标注、跟踪与穿越逻辑评测，不等于已经可以训练或验收：

- `单项取出.mp4`、`单项放入.mp4`：单方向正样本。
- `合并遮挡.mp4`、`同时通过.mp4`、`手臂遮挡.mp4`：遮挡、目标分离和不确定性样本。
- `多次取放.mp4`、`折返.mp4`、`柜内位移.mp4`：多次往返、折返和柜内运动样本。
- `开关门.mp4`、`抖动.mp4`、`空手不取.mp4`：门状态、摄像头扰动和负样本／误报样本。

部分手机视频的容器帧率元数据不规整；实现时以解码帧 PTS 为准，不以 `ffprobe` 显示的 FPS 直接推导动作时间。

## 素材用途

- 安全帽摆拍照片：检测模型主要训练素材，覆盖不同款式、颜色、尺寸、角度、距离、柜内摆放、光照和遮挡。
- 训练视频抽帧：补充真实柜体背景、运动模糊、手部遮挡和柜口位置的检测样本。
- 完整动作视频：用于 BoT-SORT、三区域状态机、事件合并及不确定处理评测。必须配人工动作真值。
- 空手伸入、柜内移动、过渡区折返、严重遮挡和多顶安全帽合并视频：用于负样本及不确定性评测，不要求强行变成确定检测结果。

照片可专门摆拍；动作视频应固定实际机位并覆盖柜内、柜口过渡区和柜外。首版检测对象是安全帽本体，不是佩戴安全帽的人。穿越过程中若目标完全不可见，应作为不确定案例，而非猜测数量。

## 首轮采集建议

首轮目标仍可参考 200–300 张照片和 10–12 段短视频，目的在于审核机位和素材覆盖，不是模型精度保证，也不是最终数据集规模。本批视频已经满足“先审查视频”的入口；下一步应从视频中选取清晰、姿态多样的帧进行标注，再判断需要补拍多少照片。试拍应包括：

- 单顶取出与放入；
- 多顶连续取出与放入；
- 取出后放回或方向交替；
- 空手伸入及柜内移动；
- 过渡区折返、停留；
- 手部／手臂遮挡、多顶重叠合并、快速通过等困难情况；过渡区始终保持在画面内。

素材数量可在机位审查和首轮标注后调整。不要把用来训练抽帧的原视频同时作为锁定测试视频。

## 检测标注规则

- 首版只用类别 `helmet`，YOLO class id 为 `0`。
- 可分辨的每顶安全帽单独标框；不能将多顶安全帽合并为一个框。
- 同一标注集采用一致的遮挡框规则。完全无法辨认的目标不猜框，应单独记录为困难或忽略样本。
- 柜内、过渡区和柜外使用同一类别及标注规则。
- 标注安全帽本体，不标佩戴者的人头或身体；帽檐、面罩、贴纸及颜色变化仍属于同一个 `helmet` 类别。
- 负样本可包含普通帽子、球体、碗状物、头部／衣物、手和包装物；若其并非安全帽，不标为 `helmet`。
- 检测标签不表达取出／放入动作；动作方向、数量和时间范围由完整视频的人工真值记录。

## 外部 PPE 数据集

`PPE.zip` 来源声明为 Roboflow PPE Detection_DATA v3，许可证为 CC BY 4.0，原始数据有六类：`Gloves`、`Vest`、`goggles`、`helmet`、`mask`、`safety_shoe`。检查发现部分标签行为是 YOLO 分割格式，而不是五列检测框；`training/prepare_dataset.py` 会只保留 `helmet`，将分割多边形转成外接检测框，并生成单类别 class `0` 数据集。原 ZIP 保留不改，转换统计和 SHA256 写入生成目录的 `conversion.json`。

## 视频真值与划分

每段视频记录相对路径、分辨率、帧率、摄像头机位、开门／关门 PTS、逐次动作方向和数量，以及无法确认区间及原因。sidecar 格式在首批素材前统一；人工确认的真值不能由模型输出替代。

先按完整视频或完整会话划分 `train`、`val`、`test`，然后才从训练视频抽帧。严禁将同一视频的相邻帧分到不同集合。锁定的测试集不参与训练，也不用于反复调阈值。
